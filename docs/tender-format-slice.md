# 投标文件格式章：原样截取与后续整改

本文是格式章这条线的维护说明。改截取规则时，同时改代码常量 `apps/api/services/tenders/slice_rules.py` 和本文「当前规则」。后续优化按文末步骤做，做完把对应步骤标成已完成，并补一句实际行为。

只处理上传的 `.docx`。PDF 不转 Word。旧版 `.doc` 需另存为 `.docx`。

---

## 1. 现在已经做到的

用户上传 Word 招标文件后，若正文里识别到投标/响应文件格式章：

1. 用下面的规则在 `word/document.xml` 里定起止。
2. 只删范围外的正文块。范围内的段落、表格、图片保持上传文件里的原 XML，不用 python-docx 重新保存。
3. 正文最后的 `sectPr`（页面设置）保留，否则 Word 打不开或页尺寸丢失。
4. 写成 `{invitationId}.format.docx`，旁边标记文件内容为 `docx-raw`。
5. 再拷一份到标书下载目录，供「预览格式章」打开。预览不再删章名、不改版式。

生成标书时用的是这份截件的副本，副本上仍会填空，并可能去掉章名扉页。那一步会改副本，不会回写截下来的原件。

## 3. 当前规则

比较前先去掉空白。章名里出现 `。` `；` `;` 则整段不当作起止。

### 3.1 从哪里开始

整段去掉「第×章 / 节 / 部分」和后面的顿号、点号后，必须正好是下列之一（`START_TITLES`）：

- 投标文件格式
- 响应文件格式
- 投标文件组成
- 响应文件组成

允许的前缀：`第` + 中文或阿拉伯数字 + `章` / `节` / `部分` / `章节`，后面可有 `、` `.` `．`。

例：`第八章、投标文件格式`、`第3部分 响应文件组成` 可以。`请阅读投标文件格式中的要求。` 不行。

整段去掉空白后超过 `START_MAX_CHARS`（现在 30）不算章名。

同一文档里有多处时，`START_PICK` 默认 `last`：目录里的同名短标题让位给正文里的最后一次。改成 `first` 则从第一次出现开始。

### 3.2 到哪里结束

从起始标题的下一块起，遇到下一条章名就停，这一条本身不进入截件。

结束章名必须带「第×章 / 节 / 部分」前缀，去掉空白后不超过 `END_MAX_CHARS`（现在 40），且它自己不是上面的格式章标题。`第九章、投标文件格式` 不结束。`第九章 评标办法` 结束。

后面没有下一章时，截到正文末尾（`sectPr` 除外，它单独留在文件尾）。

### 3.3 范围内留什么

起始标题到结束标题之前的全部正文块都留，包括章名页、目录、函件、表格、图片。不因为「这一页只有标题」再删。

页眉、页脚、样式、图片文件仍留在 docx 包里。范围外的段落删掉后，用不到的图片可能还在包内，不影响版式。

### 3.4 改规则时

1. 改 `slice_rules.py` 顶部常量。
2. 把新值写进本文第 3 节。
3. 跑 `poetry run pytest tests/test_tender_slice.py tests/test_tender_format.py::test_word_template_keeps_format_and_plain_toc -q`。
4. 重启 API 后再上传 Word。旧的 `docx` / `pdf` / `aliyun` 标记不会当成现成截件。

## 4. 识别时的两条线

两条线同时走，不要合成一份新 Word。

| 线 | 做什么 | 不做什么 |
|----|--------|----------|
| 纯文本 | 抽项目名称、工期、报价、法人等字段；用正则抽目录条目 | 不改版式 |
| 原样截取 | 产出 `{id}.format.docx` | 不填空、不重排 |

目录条目只供页面核对。按本标生成时，有 `docx-raw` 截件就用截件，不按目录另写一套 Word。

切失败（找不到标题、Word 打不开、截件小于 1KB）时，识别备注写失败原因，不落截件。此时若仍带着邀请书编号去生成，接口返回「未截到投标文件格式章」，不写说明 docx，也不改用公司固定模板。
